# Lawchart Phase 4 게이트 보고 (G-E) — AI 옵트인 경로 (F9)

- 일자: 2026-09-05
- 범위(PRD Phase 4): F9 AI 정밀 분석(옵트인, JSON 계약 동일, 규칙 폴백) + KR5 측정 체계

## 1. 설계 — 원칙 유지: 서버 없음·계정 없음

원본 plot은 서버 경유+초대제였다. Lawchart는 **BYOK(Bring Your Own Key)** 방식을 택했다:

- 사용자가 자신의 OpenAI 호환 API 키를 입력(엔드포인트·모델·키) → 브라우저에서 해당 API로 **직접** 호출.
- Lawchart 자체 서버·계정·저장 없음. 키는 사용자 브라우저 localStorage에만 보관.
- **옵트인**: 기본 꺼짐. 켤 때만 지문이 전송되며 UI에 명시 고지("지문이 입력한 API 제공자로 직접 전송").
- **폴백 100%**: AI 실패(네트워크·HTTP·응답 파손·관계 0건)면 규칙 파서로 자동 전환 — 구조적으로 보장(AI 모듈은 실패 시 null만 반환).

## 2. 산출물

| 산출물 | 내용 |
|---|---|
| `app/src/ai.js` | AI 파서 — 통제 어휘 프롬프트(사전에서 자동 도출, 단일 소스), temperature 0, 응답 JSON 추출(코드펜스·잡담 내성), 계약 검증·정규화(중복/자기자신/빈 라벨/kind 검증/날짜 정규화) → 규칙 파서와 동일 구조 |
| UI | "AI로 더 정확하게" 토글 + AI 설정 폼(엔드포인트/모델/키) + 전송 고지 + 설정·상태 localStorage 저장 |
| `evaluate.js --parser ai` | KR5 측정 — 환경변수 `LAWCHART_AI_KEY/BASE/MODEL`, 키 없으면 가드 동작, 결과 `${suffix}_ai.json` |
| `phase3/ai-smoke.mjs` | 계약 스모크 — 모의 응답 6케이스(정상/코드펜스/파손/HTTP실패/설정누락/방어) **전부 PASS** |

## 3. 검증 상태

- 계약 스모크 6/6 PASS(폴백 3경로 포함) · 문법 검사 통과 · 로컬 E2E 회귀 없음(기본 경로 무영향, AI UI 정상 로딩·콘솔 에러 0).
- **KR5(전 골드셋 AI 관계 F1 ≥ 0.92) 실측은 미실행** — 실측은 API 키 필요(건당 1회 호출·비용 발생)하며, 프로젝트 보유 키(GLM 코딩 플랜 등)의 용도·예산이 달라 임의 사용하지 않았다. 키 확보 후 아래 1줄로 측정·보고 가능:

```
set LAWCHART_AI_KEY=... && set LAWCHART_AI_MODEL=... && set LAWCHART_AI_BASE=...
node phase0/metrics/evaluate.js --parser ai --set all
```

- **판정: KR5 미달(0.912 < 0.92).** 오차 22건의 패턴(전매/계약 라벨 혼동, 배임·횡령 함의, 피해자=소유자, 수령을 지급으로 오인 등)을 프롬프트에 반영해 재측정을 시도했으나, **1차 100건 소진으로 코딩 플랜 쿼터가 차단되어 2차는 71/100 공란 처리**됨(생존 29건 정밀도 0.912로 개선 프롬프트 효과는 긍정적). 2차 기록은 `p2_all_ai_round2_ratelimited.json`으로 보관, 공식 수치는 유효 측정인 1차.
